## 编码前门槛（后续审查流程，不是交易规则）

1. 取得可复核的原始发言或案例，具有 URL、发布信息、精确定位、短摘录或准确转述及中文解释。
2. 确认规则的适用交易类型、市场环境、使用时期、执行条件、参数和例外；缺失项继续标注未知。
3. 区分固定逻辑和主观决策，明确哪些部分无法忠实机械化，不用研究者参数掩盖缺口。
4. 用原始案例核对解释的一致性，不推测未披露成交价或用回测优化参数。
5. 明确数据可得性和时间语义，避免未来信息；未知的时间定义须先澄清，不擅自补齐。
6. 证据状态不等于实现就绪；即使 VERIFIED，也须检查输入、阈值和决策优先级。

当前仅研究目录和结构可供后续接续。六项包导入测试即使通过，也不能作为交易系统已还原的证据。

### 1. 规则分层：不可混同

- **A / 确定性构件，可独立编码**：例：EMA9/21/50排序、股票市值与$5B阈值比较、上一交易日高点与1/5分钟 Opening Range 的价格事件、风险金额 = 账户权益×设定的风险比例、仓位根据入场价和止损价计算。具体数据调整、成交模型及参数来源需配置并单独测试；不能说已复刻完整 Martin 策略。
- **B / 有本人描述、选择条件不完整**：例：在回调到小时EMA支撑时选择分钟线突破；止损选当日低点还是触发K线低点；做空触及阻力后确认失败；3R/5R与EMA跟踪之间的选择。可实现为明确标为 `RESEARCH_APPROXIMATION` 的候选逻辑，但不得冒充本人唯一真实逻辑。
- **C / 关键证据缺失，不能生成固定规则**：例：扫描器 gap%/最小成交量/top N、base/tightness合格定义、AVWAP主观锚点微调、市场强弱到仓位档位的自动映射、完整 Parabolic 策略。继续取证，不能凭通用交易教材给默认值。

### 3. 编码中的真实性约束

1. 先建立 `historical_version`（至少区分2024交易法与2025交易法），不要把不同时间版本参数直接拼在一起。
2. 每项交易规则在代码或配置中关联 Rule ID 和证据等级；`RESEARCH_APPROXIMATION` 必须显式标注。
3. 所有涉及账户权益的仓位计算，需允许滑点、跳空和不可成交的情形；不能以“设置止损”当成最大亏损保证。
4. 回测必须排除未来数据：盘前、分钟K、日线收盘值在历史事件中只有对应时间形成之后才能使用。
5. 客观函数的验收按输入/输出与边界测试；高保真交易策略的验收按公开视频实例、当时行情和实际入场理由逐例核对。二者不得互相替代。
