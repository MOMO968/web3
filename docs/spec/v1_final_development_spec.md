# Martin Luk Trading System — V1 最终开发规格书

**版本**：V1.0 · 八部分审查确认稿  
**日期**：2026-10-19  
**状态**：八部分审查已确认；已同步 GitHub；Codex 编码尚未开始  
**项目仓库**：`MOMO968/web3`  
**实施目标**：尽可能忠实地还原 Martin Luk 公开描述的选股、入场、风险及离场**交易逻辑**，建立可运行的美股研究系统；**不要求逐笔重现其历史成交、具体持仓或收益率**。

> 本文件是本轮八部分审查的统一开发依据。Martin 公开原则、从实例归纳的逻辑和为了程序化补充的工程参数必须严格区分。本文中用户确定的工程参数不等同于 Martin 本人的原始参数。

## 1. 已确认的八部分决策（不可擅自改动）

| 审查部分 | 已确认结果 |
| --- | --- |
| 1. 运行方式 | **历史回测 + 每日股票扫描**；不连接真实券商，不实际下单；统一交易框架，区分不同历史风格/策略配置 |
| 2. 市场环境 | **软判断**：提示状态、风险和优先级，**不直接过滤合格信号**；纳入历史虚拟交易反馈 |
| 3. 选股系统 | **严格准入筛选**；合格股票支持按 ADR、RS、Dollar Volume、EMA、板块等**多维度排序**；不强制合成统一评分 |
| 4. 首批策略 | **Pullback Long + Breakout Long**；日线/小时线判断结构，**1/5/15分钟**触发；其他 Setup 暂不实现 |
| 5. 风险 | 默认单笔**0.5%**账户风险；初始止损距离最多**5%**；单股仓位最多**30%**；组合同时持仓计划风险最多**3%** |
| 6. 持仓管理 | **R 倍数 + 价格延伸**判断部分止盈；剩余仓位以**日线9 EMA**为主跟踪；第一批**不自动加仓** |
| 7. 技术架构 | 第一版直接提供 **Web Dashboard**；Python 策略后端 + **可替换数据源接口** |
| 8. 验收与界面 | **交易逻辑与系统正确性优先**，不设最低收益目标；**Streamlit + Python** |

### 1.1 决策之间的边界

- **选股严格过滤、市场环境软判断，两者不冲突**：必须通过选股硬条件才进入正式候选池；环境状态仅附加风险信息，不再从正式候选池中删除候选信号。
- **可配置参数、已确认的默认值并不冲突**：0.5% / 5% / 30% / 3%作为V1默认配置且为硬检查，用户在研究模式下可显式改变；回测报告要记录实际配置快照。
- **首批不自动加仓**：同一股票允许并行记录多个候选 Setup，但不得因为新信号自动增加已有股票持仓。
- **不实盘**：允许研究用虚拟交易、持仓账本及模拟成交，不调用券商下单接口。
- **首批两种策略**：EP、Pullback Short、Parabolic 等只保留扩展位，不计入 V1 功能完成范围。

## 2. 证据来源与规则治理

Martin 的原始策略并非完全公开且含主观判断，代码中至少区分：

- **DISCLOSED**：Martin 本人公开署名文章或访谈明确表达的规则，标记适用时期和例外。证据详见 `docs/research/rule_registry.md`。
- **DERIVED**：根据本人多个实际例子整理出的逻辑，不能表述为本人逐字确认的固定算法。
- **APPROXIMATION**：为自动筛选/模拟而制定的阈值、评价函数和启发式；必须可配置、文档说明、可追溯。
- **UNKNOWN**：无可靠依据的精确阈值或操作边界。不得静默填成“Martin官方默认值”。

优先保留 `source_rule_ids`、`evidence_level`、`historical_period`、`algorithm_version` 和 `parameter_profile`。例如 ADR 偏好曾公开约 >5%，但实际扫描参数和 ADR 的计算周期尚不完整；所有工程性设定应标记 APPROXIMATION。

统一框架应支持 `breakout_2024` 与 `pullback_2025` 等历史研究配置，但**不禁止**同一时间同时出现 Breakout 与 Pullback；年份不是互斥的交易开关。

## 3. 核心工作流

```text
Data Sources (pluggable adapters)
      ↓
Historical Point-in-Time Market Data + Indicators
      ↓
Strict Universe & Scanner Filtering ───────┐
      ↓                                    │
Watchlists + Multidimensional Ranking       │
      ↓                                    │
Pullback / Breakout Setup Qualification     │
      ↓                                    │
Candidate → Triggered / Invalidated         │
      ↓                                    │
Risk Validation & Position Sizing           │
      ↓                                    │
Virtual Execution → Position Mgmt → Exit    │
      ↓                                    │
Trade Feedback + Backtest Analytics         │
      ↓                                    │
Streamlit Dashboard (scan / signals / backtest / market)
                                           │
Market Context (soft annotation) ───────────┘
```

**必须共享同一策略核心**：历史回测、每日扫描、图表信号不得各自实现不同的入场算法。

## 4. Market Context（市场环境）

### 输入

- QQQ、IWM 的趋势、9/21/50 EMA位置、是否过度延伸。
- 龙头股/板块与弱势股的发展情况，广度代理指标（如有充分历史数据）。
- 截至研究时点**已完成的**虚拟交易反馈：近期盈亏R、连续止损、获利交易能否延续。

### 输出

- `AGGRESSIVE | NEUTRAL | DEFENSIVE | UNKNOWN`（工程分类，**非Martin公开固定三档模型**）。
- 提示原因、输入指标、置信度/数据完整性、市场背景警示。
- 默认**不拦截**任何已经通过选股和策略前置条件的交易信号；可在分析报表里观察不同环境的分组表现，但不得暗自改写成交结果。

### 严格时间要求

反馈仅可利用当时已经平仓的交易，未完成交易如果展示也只能使用当时可观察的浮动信息。不得从完整历史回测结果倒灌当前市场状态；热身不足标记 UNKNOWN。

## 5. Stock Selection（严格选股 + 多维度排序）

### Scanner

1. **Potent**：前一交易日表现强的股票。
2. **Pre-market**：当前交易日盘前向上跳空且成交活跃的股票。
3. **Leader**：过去约一个月表现领先的股票。

### 硬条件与排序的分离

- **严格过滤**：在具体配置中明确最低数据完整性、交易所/证券类型、价格、流动性、波动率、趋势/扫描器触发等可执行条件；未满足者不进入合格候选池。
- **参数来源**：Martin 有明确来源的条件按其语境保留；他未公开的阈值可由工程配置提出，但必须贴 `APPROXIMATION`，**不允许未经讨论就把一个任意数值当作他的原始规则**。
- **宽松偏好不能暗中改成硬规定**：如 ADR>5% 是历史偏好，若决定纳入严格过滤，只能在配置中显式作为工程筛选选择，并允许研究人员关闭。
- **排名显示**：ADR、Dollar Volume、RS、9/21/50 EMA、行业、榜单命中原因、Gap等单列展示、分别排序，不引入一个必须使用的综合评分。

### Watchlists

- Screening、Small Cap（历史披露市值<$5B）、Lead（EMA9>EMA21>EMA50）、Lag（EMA9<EMA21<EMA50）、Mediocre（交错排列）。
- 允许同一股票具有多个互不排斥的标签；等号边界、历史数据不全、暂停交易等场景显式标记UNKNOWN或数据不可用。
- 历史股票池、退市证券、历史市值/行业、榜单成员尽量按当时真实状态保存，避免幸存者偏差；拿不到数据要在回测中披露覆盖范围。
- 缺历史盘前数据时不能使用日间行情冒充；可返回 `PREMARKET_UNAVAILABLE`，用户明确选择仅对可用Scanner回测时要留下记录。

## 6. 首批策略与入场

### 6.1 Pullback Long

1. **日线前置条件**：强势或健康向上趋势，结构未明显破坏；可配置过度延伸过滤。
2. **高周期回踩**：靠近日线/小时线9/21 EMA、已确认AVWAP锚点或历史价格支撑；要有可操作的支撑定义。
3. **低周期确认**：1/5/15分钟反转和向上触发（例如突破前一根已完成K线高点）；具体触发分支按配置记录。
4. **风险复核**：结构性止损合理、止损距离≤5%、仓位及组合预算允许。

**禁止**只因价格触碰均线，就自动输出买入；主观“第一次高质量回踩”、AVWAP锚点、过伸程度属于明确标注的可配置近似。

### 6.2 Breakout Long

1. 日线/周线已有强度，近期出现可量化的整理、波动压缩或合格 Base。
2. 可选触发：前日高点、完整的首根1/5分钟开盘区间高点、经定义的日内/多日阻力突破。
3. 触发必须在突破形成时满足上下文、止损和组合风险限制。
4. Base成熟度、Tightness窗口及门槛属于工程近似，不把简单 `high > previous_day_high` 视为完整策略。

### 6.3 信号状态机

- `CANDIDATE`：已通过硬选股及Setup资格，尚未触发入场。
- `TRIGGERED`：在指定已结束/已知时刻，触发条件及风险限制满足，记录触发时间与价格假设。
- `INVALIDATED`：支撑/结构破坏、交易窗口过期、止损超限、数据不足或其他事先定义的失效条件；应记录失效原因。

为了避免语义冲突，未通过硬选股的股票是 `FILTERED_OUT`（非Candidate）；超出风险限额的事件可记 `REJECTED_BY_RISK`（非成交信号）。这些辅助状态可独立记录审计日志。

### 6.4 多周期与时间线

- 日线/小时线提供结构；1分钟是最低原始频率，5/15分钟可合成；60分钟定义与美股交易时段锚定规则需明确。
- 入场触发不能读取尚未完成的K线；前一日高点必须来自已结束的交易日。
- 必须明示美东时区、夏令时、盘前/常规时段和开盘区间的计算约定。

## 7. 风险、仓位及虚拟执行

### 7.1 四项默认硬约束

| 风控项 | 默认值 | 处理 |
| --- | --- | --- |
| 单笔计划账户风险 | 0.5% | `equity × 0.005`，基于触发时权益 |
| 最大初始止损距离 | 5% | `(expected_entry - initial_stop) / expected_entry ≤ 0.05` |
| 单股仓位价值上限 | 30% | `position_notional ≤ equity × 0.30` |
| 同时持仓总计划风险 | 3% | 新开仓加上存量持仓的未释放计划风险≤`equity × 0.03` |

四项均默认启用。最后一项为用户选择的**工程风控参数**，不是Martin自述原始规则。

### 7.2 仓位计算与优先顺序

1. Setup提供有技术结构依据的初始止损；不能为凑百分比而无根据地移动止损。
2. 结合预计成交价与止损价计算理论每股风险，并预留模拟费用/滑点处理。
3. `shares_by_trade_risk = floor(trade_risk_budget / effective_risk_per_share)`。
4. `shares_by_symbol_cap = floor(0.30 * equity / expected_entry)`。
5. 再限制组合剩余风险预算、剩余现金及最小交易单位，取所有约束中的最小允许股数。
6. 允许股数=0、价格不合理、缺关键数据则不模拟成交，并记录拒绝原因。

**组合风险记账需要明确约定**：第一版建议采用持仓中尚未释放的初始计划风险；卖出部分减少对应持仓风险，止损上移时如何降低风险以可配置且可审计的规则实现。不得用历史最终盈利提前“释放”当时风险预算。若多个信号同一时间产生，以确定性顺序进行资金/风险预留并报告拒单。

### 7.3 成交与止损模拟

- 产生信号不等于已成交；明确 `signal_at`、`order_eligible_at` 与 `fill_at`，避免同根未来成交。
- 止损单与开盘跳空要模拟不利成交及滑点，不能默认最大亏损恰为0.5%。
- 手续费、滑点、股票拆分/分红处理方式通过统一配置提供，并在回测报告列出。
- 首批为现金账户约束（Long-only），默认禁止无资金买入/隐性杠杆；如要支持融资另行审查。

## 8. 盈利管理与退出

### 8.1 部分止盈

- 采用**R倍数 + 价格延伸**的联合判断；首次减仓的R阈值、延伸测量方法、每次减仓比例等暂作为可配置 `APPROXIMATION`，不擅自确定为 Martin 唯一模式。
- 本人历史个案中有3R、5R、减仓15%、减半等不同做法，这些只用于说明可选行为，**不是统一全局默认值**。
- 每个减仓阶段只允许触发一次，并记录入场初始R、触发原因、减仓股数及剩余持仓；不允许因价格反复达到门槛无限重复减仓。

### 8.2 剩余仓位跟踪

- 日线9 EMA为主：优先采用**日线收盘确认**的研究模式；只能在日线收盘完成以后作出退出决定，默认下一个可成交时点执行，不可以当日收盘前预知收盘价。
- 可在后续配置中加入小时线保护止损，但不是第一版强制默认。
- 初始保护性止损始终存在；可配置的动态止损不能在无说明情况下增大已有计划风险。
- 市场转弱作为软警示，不自动强行清仓。

### 8.3 加仓与同股多策略

- **不自动加仓**。
- 同一只股票多种Setup的候选信号可同时保留用于研究，虚拟账户默认一只股票最多一组净多头仓位，避免双算风险。

## 9. 可替换行情数据架构

### 9.1 必备接口

建议 `MarketDataProvider` 抽象提供：

- 历史/最近的OHLCV（日、小时、1分钟；5/15分钟可由1分钟聚合）；
- 盘前行情（若可用），相关覆盖与错误语义；
- 股票元数据（行业、市值、交易所、退市等，注明是否历史时点数据）；
- 市场基准QQQ/IWM，交易日历及企业行为；
- 数据来源、复权状态、最晚可观察时刻与数据质量元信息。

### 9.2 一致性与复现

- 本地缓存/数据快照标明 provider、数据版本、时间范围、时区、复权口径、覆盖率。
- 数据源切换不应改动核心策略算法；不同源数据差异通过兼容性测试明确展示。
- 如暂时无法获得历史分钟数据或盘前数据，**不得虚构扫描或假装分钟级回测已经完整实现**。允许针对有限股票及时间窗口建立可复现演示，并在界面注明覆盖范围。

## 10. Streamlit Web Dashboard（首版必需）

至少具备四个可用页面：

| 页面 | 必须具备的功能 |
| --- | --- |
| Market Overview | QQQ/IWM趋势、环境标签、信号与虚拟交易反馈、数据更新时刻、状态依据 |
| Stock Scanner | 选择日期/数据源/过滤配置，运行Potent/Pre-market/Leader；查看被筛除原因、合格候选、ADR/RS/EMA等多维排序与缺失字段 |
| Strategy Signals | 筛选Pullback/Breakout，展示Candidate/Triggered/Invalidated、触发时间与价格、止损、预计风险和K线图标记 |
| Backtest Analytics | 选择期间/策略/参数并运行回测；显示权益曲线、最大回撤、胜率、平均R、成交账本、逐笔原因与导出 |

用户不必使用命令行即可完成一次带有效数据的扫描与回测。图表不得伪装为真实行情；研究参数（APPROXIMATION）在页面可识别。运行失败给出明确原因，不展示貌似正常的空结果掩盖错误。

### 10.1 技术边界

- Python 提供数据与策略核心、组合模拟和结果数据模型；Streamlit只做交互、可视化及任务发起。
- 耗时任务提供执行状态、缓存和错误处理；避免页面反复刷新导致重复回测。
- Web不可包含下单按钮、交易凭证输入或真实券商下单逻辑。

## 11. Codex 分阶段实施计划

已有仓库具备Python、pytest、Ruff和CI骨架，应在原有结构上增量开发，**避免推翻已合并的基础设施**。

| 阶段 | 交付范围 | 必须通过的阶段验收 |
| --- | --- | --- |
| P1 | 数据契约、provider adapter、交易日历、1→5/15/60分钟聚合、EMA/ADR/RS | 时间线、时区、单位与指标基准测试，缺数据行为有定义 |
| P2 | 三种Scanner、严格准入、历史Watchlist、Market Context软标签、交易反馈数据契约 | 指定历史日期可复现候选及拒绝原因；环境标签不删除信号 |
| P3 | Pullback Long和Breakout Long，Setup状态机，1/5/15分钟触发 | 合成行情正例、反例、过期、破位、跨时段无未来函数测试 |
| P4 | 单笔/组合风控、模拟成交、止损、部分止盈、日线9EMA退出、回测账本 | 0.5/5/30/3默认约束、重复减仓防护、跳空滑点及权益平衡测试 |
| P5 | Streamlit四页面、图表、配置、扫描和回测入口、导出及整体验收 | 用户在浏览器独立完成扫描/回测；与CLI/后端输出一致 |

**界面属于V1验收范围**：可以在P1–P4阶段建立薄UI骨架，但P5完成后才宣称最终V1交付。每次Codex阶段完成需给出中文工作报告、实现清单、验证命令与结果、缺陷和后续计划；保持项目`AGENTS.md`规范。

## 12. 终验收标准

### A. 数据正确性

- 交易日历、美东夏令时、盘前/常规交易区分正确；多周期K线只使用已知数据。
- 历史数据/证券池使用当时可用信息；无法做到时披露限制。
- 缺失分钟线、盘前数据、历史市值时必须显式报错/退化，不暗中替代。

### B. 策略行为正确性

- Scanner硬准入与市场环境软提示准确分离。
- 不符合Setup的单纯EMA触碰、孤立前高突破不应自动成交。
- 触发、失效和被风控拒绝的信号可追踪；同一输入及配置得到一致结果。

### C. 风险与回测账本正确性
